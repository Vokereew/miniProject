## Использование ИИ в проекте

В рамках этого проекта я активно использовал ИИ как инструмент разработки. С его помощью были реализованы фронтенд, механизм идемпотентности, а также ускорена разработка серверной части.

ИИ хорошо справился с большей частью типовых задач и позволил значительно сократить время разработки. При этом я самостоятельно проверял и дорабатывал предложенные решения.

Основные ошибки ИИ были связаны с реализацией идемпотентности и использованием idempotency key, а также с некорректным масштабированием некоторых элементов фронтенда. Эти моменты я исправил самостоятельно после проверки реализации.

В целом проект оказался достаточно компактным, поэтому ИИ хорошо справился с основной частью работы и позволил быстрее пройти путь от идеи до готового приложения.


## Что сделано

- API для получения списка поездок за выбранную дату
- API для получения сводки за день: число поездок, выручка, комиссия, на руки, разбивка по наличным/карте
- API для добавления поездки с проверкой данных:
  - сумма должна быть больше 0
  - окончание поездки должно быть позже начала
  - неверный тип оплаты или отрицательная комиссия отклоняются
- защита от дубликатов по `idempotency_key` и по идентификатору поездки
- авто-генерация ID поездок в формате `t1`, `t2`, `t3`, ...
- веб-интерфейс для выбора дня, просмотра сводки и добавления поездки, разнесённый в отдельные файлы: `web/index.html`, `web/styles.css`, `web/app.js`
- тесты на расчёт сводки, API и идемпотентность по `idempotency_key`

## Запуск

```bash
go run .
```

По умолчанию сервис работает на:

- http://localhost:8080/
- API: http://localhost:8080/api/summary?date=2026-10-01

## Формат поездки

```json
{
  "idempotency_key": "req-abc-123",
  "start": "2026-10-01T08:10:00+05:00",
  "end": "2026-10-01T08:32:00+05:00",
  "amount": 2400,
  "payment": "card",
  "commission": 360
}
```

Если отправить повторно такой же `idempotency_key`, новая поездка не будет создана. Поле `id` генерируется сервером автоматически, поэтому его не нужно передавать вручную.
